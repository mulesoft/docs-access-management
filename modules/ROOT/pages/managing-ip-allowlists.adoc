= Managing IP Allowlists in Access Management

Restrict access to your Anypoint Platform organization to trusted networks by configuring IP allowlists in Access Management. You can enforce IP restrictions for both user sign-ins and connected app token requests to reduce credential abuse, prevent unauthorized automation, and meet compliance requirements.

[NOTE]
--
* This feature is available only for US and EU commercial clouds.
* IP allowlisting for user sign-ins applies only to users who sign in with Anypoint Platform credentials. It doesn't apply to users who authenticate through an external identity provider (IdP) using SSO.
* IP allowlisting for connected apps applies at the root organization level and covers all sub-organizations.
* Only IPv4 addresses are supported.
* Your organization can define up to 25 CIDR blocks total, shared across both the user sign-in and connected app token request policies.
--

== Before You Begin

* Make sure you have the root Organization Administrator permission for your organization.

[enable-disable-ip-allowlisting]
== Configure IP Allowlisting for User Sign-ins

Enable or disable IP allowlisting for your organization's user sign-ins in Access Management. When this feature is enabled, only sign-ins from IP addresses in allowed CIDR blocks succeed. Sign-in attempts outside the IP allowlist are blocked and logged.

. Sign in to Anypoint Platform using an account that has the root Organization Administrator permission.
. Select *Access Management* from the image:gear.svg["gear icon",20] menu.
. In the Access Management navigation menu, select *Security Settings*.
. In *IP Allowlist*, enter the IP address CIDR blocks to allow to sign in. For example:
* IP Address CIDR: `192.0.2.0/24`
* Description: `NE office network`
+
[NOTE]
All defined CIDR blocks apply to all users in your organization unless they're exempted.
. (Optional) Click *Add* or *Remove* to add and remove CIDR blocks.
. Switch the *Enforce IP restrictions for login* switch on or off to activate or deactivate defined IP restrictions for all users within your organization.
+
If there aren't any CIDR blocks configured, this option is disabled.
. Click *Save*.
+
After you enable enforcement, users attempting to sign in from an unauthorized IP address receive a `403 Forbidden` error with the message `IP address not allowed for this organization`.

[ip-allowlist-exemptions]
== Exempt Users from IP Restrictions

You can exempt specific users from the organization-wide IP allowlist restrictions.

[NOTE]
Root organization administrators are subject to IP enforcement unless explicitly exempted, and they're allowed to self-exempt.

. Sign in to Anypoint Platform using an account that has the root Organization Administrator permission.
. Select *Access Management* from the image:gear.svg["gear icon",20] menu.
. Select *Users*.
. Select the user to exempt and then select *Settings*.
. Select *Exempt user from IP restrictions*, and then click *Save*.

[configure-ip-allowlisting-connected-apps]
== Configure IP Allowlisting for Connected Apps

Restrict which IP addresses can request OAuth 2.0 tokens for connected apps in your organization. When this feature is enabled, any `POST /api/v2/oauth2/token` request that originates from an IP address outside the allowlist is blocked and logged.

Connected apps using client credentials are used by CI/CD pipelines, Anypoint MQ Connector, Object Store v2, and other programmatic integrations. Before you enable this feature, identify where each connected app runs and whether its outbound IP address is static and uniquely yours.

[WARNING]
====
Enabling IP allowlisting for connected apps can break running integrations if the outbound IP address of the Mule runtime is dynamic or shared with other tenants. Review the deployment model guidance below before enabling enforcement.
====

[connected-app-deployment-models]
=== Identify Your Deployment Model

Use the following table to determine the recommended action for each deployment model before enabling connected app IP allowlisting.

[%header,cols="25,35,40a"]
|===
| Deployment Model | Outbound IP Behavior | Recommended Action

| CloudHub without static IP (default)
| Dynamic; drawn from an AWS EC2 pool and can change without notice
| Exempt the connected app from IP enforcement. These IPs can't be reliably allowlisted.

| CloudHub 2.0 Shared Space
| Egress IPs are shared across all customers in that space and aren't static. Allowlisting them provides no meaningful security isolation.
| Exempt the connected app from IP enforcement. These IPs aren't unique to your organization.

| CloudHub  with static IP enabled
| Fixed IP address; you opt in through Runtime Manager app settings on the *Static IPs* tab
| Add those static IPs to the allowlist. You can allowlist up to 2× your production vCores allocation.

| CloudHub 2.0 Private Space
| Static egress IPs assigned to the Private Space; unique to your organization
| Get the IPs from the Private Space settings in Runtime Manager and add them to the allowlist.

| Runtime Fabric
| Your own NAT gateway (AWS Elastic IP, Azure NAT Gateway, or GCP Cloud NAT)
| Retrieve the outbound IPs from your cloud provider account and add them to the allowlist.

| Hybrid (Mule runtime on a customer VM or bare metal)
| Your own network
| Your network team controls and knows these IPs. Add them to the allowlist.

| CI/CD or build servers
| Your own infrastructure
| Your network team knows these IPs. Add them to the allowlist.
|===

[NOTE]
MuleSoft-managed platform services (internal connected apps) are automatically exempt from connected app IP enforcement. You can't change this exemption.

=== Enable or Disable IP Allowlisting for Connected Apps

. Sign in to Anypoint Platform using an account that has the root Organization Administrator permission.
. Select *Access Management* from the image:gear.svg["gear icon",20] menu.
. In the Access Management navigation menu, select *Security Settings*.
. In *IP Allowlist*, confirm that at least one CIDR block is defined. CIDR blocks are shared between the user sign-in and connected app token request policies.
. Switch the *Enforce IP restrictions for connected app token requests* switch on or off to activate or deactivate IP restrictions for all connected apps in your organization.
+
If there aren't any CIDR blocks configured, this option is disabled.
. Click *Save*.

[connected-app-exemptions]
=== Exempt a Connected App from IP Enforcement

If a connected app runs on infrastructure where the outbound IP address is dynamic or shared, such as CloudHub without static IPs or CloudHub 2.0 Shared Space, exempt that app from IP enforcement rather than trying to allowlist unpredictable IPs.

. Sign in to Anypoint Platform using an account that has the root Organization Administrator permission.
. Select *Access Management* from the image:gear.svg["gear icon",20] menu.
. In the Access Management navigation menu, select *Connected Apps*.
. In the *Owned Apps* section, click the connected app to exempt.
. Select *Exempt from IP restrictions*, and then click *Save*.

[audit-logging]
== Audit Logging

These actions are logged in the audit log:

* Create, update, and delete actions performed by an organization administrator on the allowlist
* Sign-in failures due to IP restrictions
* Blocked connected app token requests due to IP restrictions
